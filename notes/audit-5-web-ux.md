# Phase 5 — Web / UX Audit

_Manual code review of `web/app.js`, `web/daily.js`, `web/topics.js`, `web/practice.js`, `web/styles.css`, `web/template.html`._

## TL;DR

- **No XSS holes** in normal content flow. All user-facing strings pass through `esc()` / `inline()`. `innerHTML` is only set with:
  - `mdToHtml(doc.markdown)` — markdown is authored by us, no untrusted input.
  - `promptHtml` / `bodyHtml` / `html` fields — server-generated by `build.mjs` `rewriteHtml()` which strips inline styles/scripts, no untrusted input either.
  - JSON payloads (fc-deck, runnerHydrated) — properly escape `<` via `.replace(/</g, "\\u003c")`.
- **No `fetch()` for lesson data.** Only fetch is `dictionaryapi.dev` for optional IPA lookup (graceful null on error → OK for `file://`).
- **2 bugs cần fix** (chi tiết dưới).
- **1 UX gap** (kết quả phiên cũ trong history không xem được câu sai chi tiết).
- **Bundle syntax check xanh** (Phase 0 đã confirm).

## Findings

### W1 — [HIGH] `loadDailyLesson` pending cache không clear khi fail

`web/daily.js` L27-44: `pending[key]` được gán promise nhưng không cleanup khi promise reject. Kết quả: nếu load `dist/daily/lesson-XX.js` fail lần đầu, mọi lần gọi `APP.loadDailyLesson(key)` sau đó return **cùng promise đã reject** — không retry được. User bấm F5 hay quay lại cũng vẫn thấy lỗi.

**Fix**: xoá `delete pending[key]` trong `.finally` để lần sau có thể inject lại `<script src>`.

### W2 — [MEDIUM] Practice result từ history không xem được câu sai

`web/practice.js` L114 `pushHistory()` KHÔNG lưu `result.detail` (chỉ lưu `breakdown`, `score`, `total`, `answers`, `questions`). Khi user click history entry → `practiceResultPage()` L494 reconstruct `session.result = { ..., detail: [] }`. Kết quả: `wrongList` filter empty → hiển thị **"Hoàn hảo! 🎉"** dù trước đó user có sai.

**Fix option 1** (đề xuất): thêm `detail: r.detail` vào history push (tăng size localStorage nhưng chấp nhận được — max 50 entries).
**Fix option 2**: hiển thị message "Chi tiết câu sai chỉ khả dụng ngay sau khi làm bài" để không misleading.

Áp dụng **option 1** — user học tiếng Anh nên cần review câu sai đã cũ.

### W3 — [LOW] Dictionary lookup silently fails on file://

`web/app.js` L73-84 `dictLookup()` calls `fetch("https://api.dictionaryapi.dev/...")`. Trên `file://` sẽ fail CORS/network. Đã có try/catch → return null → UI hiển thị "Đã đọc bằng giọng máy. (Không có mạng hoặc không tìm thấy từ.)". Copy hơi mơ hồ (không phân biệt "không mạng" vs "không tìm thấy").

**Fix option**: split thành 2 message. Skip trong pass này — nhỏ, không blocker.

### W4 — [LOW] Search reset on every navigation

`web/app.js` L381 `go()`: `el("search").value = ""` reset ô tìm kiếm mỗi lần chuyển page. UX: user tìm "past tense" rồi click nav → search bị xoá. Có thể là intentional (mỗi page có state search riêng), nhưng thiếu affordance.

**Fix option**: giữ nguyên (intentional). Skip.

### W5 — [LOW] Duplicate CSS accent rule for `stage`

`web/styles.css` L39: `#content[data-page="stage"], .app[data-page="stage"] { ... }` — bind BOTH selectors. Các page khác chỉ bind `.app[data-page="..."]`. Không có tác dụng khác biệt (cả 2 đều accent xanh). Micro-cleanup.

**Fix option**: skip. Minor.

### W6 — [LOW] `practicePage` cho phép `totalInput` ngoài min/max attr

HTML input có `min="5" max="200"` nhưng JS đọc `parseInt(totalInp.value) || 30` không clamp. User type 500 → 500 câu. Không bug, nhưng nếu 500 vượt total candidates thì `samplePool` return short → user thấy shortage message. Đủ graceful.

**Fix option**: skip.

### W7 — [INFO] Flashcard keydown listener cleanup

`web/daily.js` L340 và `web/topics.js` L278: `document.addEventListener("keydown", onKey)`. Cleanup dựa vào self-check `if (!document.body.contains(wrap)) { removeEventListener; return; }` trong mỗi keydown event → OK. Không leak vì self-terminates.

### W8 — [INFO] Race trong `loadDailyLesson` (successful path)

Multiple concurrent `loadDailyLesson(key)` calls đều nhận cùng promise từ `pending[key]` — safe. Đơn xin ngoại lệ: fix W1.

### W9 — [INFO] `mdToHtml` recursive blockquote

`web/app.js` L119 blockquote đệ quy `mdToHtml(buf.join("\n"))`. Không stack overflow trong dữ liệu thực (blockquote nested tối đa 1-2 lớp). OK.

### W10 — [INFO] Question kind coverage trong practice runner

5 kinds được render (`single_choice`, `multi_select`, `fill_blank`, `matching`, `open_or_video`+fallback). `info` được filter out khỏi practice pool (samplePool `r.qkind !== "info"`). `open_or_video` render "Loại câu open_or_video không chấm tự động — bỏ qua" — grade luôn false. Nhưng samplePool đã filter allowedTypes → nếu user không tick `open_or_video` thì không bao giờ có trong pool. Trong preset defaults, `open_or_video` không được chọn → OK.

## Kết luận

Bug thật: **2 findings** (W1, W2). Áp dụng fix trong section tiếp theo.

Không có structural bug nào ở render, grading, sampling hoặc storage.
